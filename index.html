How I work

How I
work

Four things I try to do on every project, each with an example.

01

Understand who it's for.

Before writing code, I try to understand who will use it and what's getting in their way.

In practiceSaralya's interview flow was built around applicants in tier-3 cities, so speed and parsing Hindi numbers came first.
02

Agree on a number.

I like deciding early how we'll know it worked, so we know when we're done.

In practiceFor the small-model work: response latency and LLM calls per interview.
03

Build a working version early.

I can build a working prototype in React and FastAPI, so we can test it with real people sooner.

In practiceNexus and Flexi5 are both live products I built end to end.
04

Test it and fix the cause.

When something goes wrong in testing, I look for the cause instead of a quick patch.

In practiceFlexi5 was tested with 20–25 people. At Saralya, wrong numbers from the model got rule-based checks instead of just a better prompt.

Problem
